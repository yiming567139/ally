# 「油迹」摩托车油耗记录 App · 设计文档

## 1. 产品概述

| 项 | 内容 |
|---|---|
| 定位 | 摩托车加油记录 + 油耗分析，**单机、无账号、数据全本地** |
| 用户 | 车主本人（支持多辆车） |
| 平台 | Android 优先（直接装 APK），Flutter 跨平台可后补 iOS |

## 2. 技术选型（结论：方案 1 · Flutter）

针对你问的"前端尽量做好看，用 1 还是 2"——**推荐 Flutter**：

| 对比项 | Flutter | React Native / Expo |
|---|---|---|
| 渲染方式 | 自绘引擎（Impeller），**所有机型像素级一致**，深色模式/自定义 UI 不受平台组件限制 | 映射原生组件，定制深度依赖第三方库 |
| 动效表现 | 动画系统是框架核心能力（Hero、隐式动画、spring 曲线），**做"好看"成本低** | 需要额外库（Reanimated），调体验更费劲 |
| 图表 | fl_chart 成熟好用 | victory-native / react-native-svg 手工感重 |
| 适合度 | 工具类 + 重 UI 定制 = Flutter 主场 | 如果你本身熟 React/TS，则维护成本更低 |

> 结论依据：本项目 UI 全自定义（油量表、数字翻牌、图表卡片），Flutter 自绘 + 动画优势明显；不必顾虑 iOS/Android 双端一致性。

技术栈清单：

- **框架**: Flutter 3.x + Dart
- **状态管理**: Riverpod
- **本地库**: drift（SQLite ORM，类型安全、响应式查询，数据变动 UI 自动刷新）
- **图表**: fl_chart
- **图标**: lucide_icons（统一线性图标，禁用 emoji 图标）
- **提醒**: flutter_local_notifications（二期保养提醒）
- **字体**: 中文 MiSans / Noto Sans SC，数字与拉丁 Poppins（tabular figures）

## 5. 数据模型（drift / SQLite）

### vehicles 车辆表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT NOT NULL | 车型号，如「春风 450SR」 |
| fuel_grade | TEXT NOT NULL | 所加油品 92/95/98（历史条目继承显示，单笔不可改，不做标号间对比） |
| created_at | TEXT | ISO 8601 |

**删除规则**：车辆支持删除，删除时**级联清空该车的全部加油记录**（`ON DELETE CASCADE` 或应用层先删 fill_ups 再删 vehicles）。危险操作二次确认，弹窗明确"将同时清空 XX 条加油记录"，并建议先导出 CSV。删除后无车辆则回到空状态引导页。

### fill_ups 加油记录表（核心）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| vehicle_id | INTEGER FK → vehicles | |
| filled_at | TEXT NOT NULL | 加油时间，默认现在 |
| odometer | REAL NOT NULL | 总里程读数 |
| is_full_tank | INTEGER NOT NULL | **是否加满（计算边界开关）** |
| volume_l | REAL NOT NULL | **升数（唯一录入的量值）** |
| distance_since_last | REAL? | 无总里程表的车：填「距上次行驶里程」 |
| note / photo_path | TEXT? | 可选 |
| created_at / updated_at | TEXT | |

**录入校验规则**：`volume_l` 必填（大数字键盘）；odometer 小于上一条 → 黄色警告但允许保存（录错总里程常见）；删除需二次确认 + 可撤销 toast。

**价格模型**：不逐笔记录油价。设置页维护一个**常规默认油价（元/L）**，全局所有金额与成本（单笔金额、月度油费、每公里成本）一律按 `volume_l × 默认单价` 折算；修改默认价只影响之后的新统计口径。

### maintenance_logs 保养表（二期）

type(机油/机滤/空滤/链条/火花塞)、odometer、date、interval_km、interval_days → 推算下次提醒。

## 6. 核心算法：满箱法

**原则：只有「上次加满 → 本次加满」构成的区间，油耗才可信；未加满的记录只参与累计，不作为计算边界。**

对每辆车按 `filled_at` 排序后：

1. 取所有 `is_full_tank = 1` 的记录为锚点。
2. 相邻锚点 A → B 构成一个计算段：
   - `distance = B.odometer − A.odometer`
   - `fuel = sum(volume_l of records in (A, B])`（B 这一笔补满了油箱缺口，所以含 B 不含 A）
   - `区间油耗 L/100km = fuel / distance × 100`；`km/L = 100 / L100`
   - `每公里成本 = 段内油量 × 默认单价 / distance`
3. 边界情况：
   - **第一条记录**：仅作基准，不算油耗；
   - **最后一个加满锚点之后**（尾巴）：进入「本箱进行中」状态，不显示区间油耗，只累计已跑里程/已加油量；
   - **无总里程表的车**：用 `distance_since_last` 直接累加段里程；
   - odometer 倒退/相等：标记异常，提示检查，该段不计入均值；
   - **误差提示**：小油箱「跳枪」早晚误差可达 ±0.3L/100km，历史页区间油耗标注"参考值"，引导文案建议固定同一把枪自动跳枪。
4. 全局指标：平均油耗 = 首个锚点后总油耗 / 总里程；**所有金额（单笔、月度、每公里成本）= 油量 × 设置页默认单价**；单位设置支持 L/100km ↔ km/L 全局切换。
5. **不做实时油箱余量**（v0.5 定稿决策）：App 只在加油录入时才获得里程数据，平时无法知道当前里程，因此"剩余油量 / 预计续航"没有数据基础，不做。用户问题"一箱油能跑多远、什么时候该加油"改由**纯记录统计**回答：
   - `满箱续航（平均）= 无中途补加的满锚段里程均值`（有补加的段混入了补加油量，不代表一箱油的真实能力）；
   - 首页「满箱续航」卡展示：平均每箱 / 最近一箱 / 统计段数；
   - 唯一展示"本箱实时距离"的时刻是**录入时**：里程填入后显示「+X 本箱」，与平均续航对照（如"本箱才跑 66km，距平均 261 还早"）；
   - 若未来想粗估当前余量，可用 `距上次加油天数 × 日均里程` 外推，但双重估算误差大，暂不实现。

## 7. 页面详细设计

### 7.1 首页（Dashboard）

```
┌──────────────────────────────┐
│ [春风450SR ▾]   平均油耗            │
│                              │
│   3.36        L/100km        │  ← Display 大数字 + 翻牌动效
│   ≈ 29.8 km/L                │  ← 主单位可切换，副单位常显换算值
│                              │
│ ┌ 满箱续航 ─────────────────┐ │
│ │ 平均 261 km · 最近 290 km · 7 段 │ │  ← 无中途补加的段实测均值（无实时油量表）
│ └──────────────────────────┘ │
│ ┌ 本月油费 ¥71.5 · 本月进行中  ┐ │
│ ┌ 每公里成本 ¥0.26（默认价折算）┐ │
│ ┌ 上次加油 ─────────────────┐ │  ← 时间·升数·默认价 + 区间油耗
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

- **首页不放「记一笔」按钮**：新增记录的入口唯一，即底部导航中央的「＋」悬浮按钮（FAB），点击弹出 7.2 的录入 sheet。全 app 只此一个录入入口，避免重复 CTA。

### 7.2 记一笔（Bottom Sheet，单手场景）

- 字段顺序即操作顺序：**升数输入**（大数字键盘，唯一量值录入）→ 里程（默认上次 + 常骑日均值预填）→「加满」大开关（默认开，未加满显示醒目琥珀描边提醒"不计入区间油耗"）→ 备注（可选）→ 时间（默认现在，右上角胶囊显示）。
- **不支持按金额录入**；里程字段旁只读显示「本次金额」折算值（升数 × 设置默认油价），不可改。
- **不采集加油站信息**：减少录入步骤保持"30 秒一笔"；如需备注在哪加的油，写进备注即可。
- 校验就地显示（on blur）；保存按钮在无升数时禁用。
- 保存：haptic 轻震 + sheet 下滑收起 + 首页新油耗卡片高亮浮现。

### 7.3 记录（历史）

- 倒序按月分组；顶部显示累计加油/累计花费/累计里程；每条：日期、升数、里程、**折算金额**、**区间油耗**、备注。
- 加满记录带「FULL」徽章（它是区间油耗计算的锚点）；未加满记录：灰显虚线卡片 + 「PARTIAL」徽章，油耗位显示"—"。
- 标号不在条目内展示（跟随车辆设置，见车辆副标题）。
- 左滑编辑/删除；删除后 toast 可撤销。

### 7.4 统计

- 油耗趋势折线（区间油耗 + 均值虚线，点击数据点显示详情 tooltip）；
- 月花费柱状图（油量 × 默认油价折算，卡片注明折算口径）；
- 时间粒度切换（3月 / 半年 / 全部）；空状态给插画 + 引导，不出空白坐标轴。

### 7.5 车辆管理 & 设置

**车辆管理**（设置页内「我的车辆」入口）：车辆仅维护**车型号 + 所加油品**两项，车辆卡片上显示该车记录条数；支持删除车辆——删除时级联清空该车全部加油记录（二次确认，弹窗写明记录条数，建议先导出 CSV）。

**设置项清单**：

| # | 设置项 | 说明 |
|---|---|---|
| 1 | **常规默认油价**（元/L） | 全局唯一价格来源；所有金额/成本 = 升数 × 默认价；改价只影响之后的统计口径 |
| 2 | **油耗单位** | L/100km ↔ km/L 主单位切换，副单位常显换算值 |
| 3 | **主题** | 跟随系统 / 深色 / 浅色 |
| 4 | **数据管理** | 导出 CSV / 备份到文件 / 从备份恢复 / **清空加油记录** |
| 5 | **关于** | 版本信息、满箱法计算说明 |

**清空加油记录**：点击弹出确认框（红色危险操作，写明“将清空 X 条加油记录，车辆信息保留”），确认后清空全部 `fill_ups`（所有车辆），车辆基本信息保留；确认框内建议先备份。与「删除车辆」的区别：删除车辆是清掉单个车辆及其记录，清空加油记录是保留所有车辆、只清记录。

**明确不做的设置**：账号/登录（单机 local-first）、逐笔油价（已由全局默认价取代）、提醒类设置（保养提醒属二期）。

## 8. UX 质量红线（实现时逐条验收）

1. 无 emoji 图标；lucide 线性图标统一线宽，同一层级不混用 filled/outline。
2. 深浅两套主题**分别**验对比度：主文字 ≥ 4.5:1，次文字 ≥ 3:1；分隔线两套都可见。
3. 所有可点元素有按压反馈（scale/透明度），不位移布局。
4. 表单 label 常显（不靠 placeholder）；错误提示就地 + 给修复建议。
5. 底部导航 ≤ 5 项、图标+文字；返回行为可预期，返回恢复滚动位置。
6. 数字一律 tabular figures；列表虚拟化（记录 > 50 条）。
7. 安全区适配（手势条/挖孔），固定底栏留出 padding。
8. 尊重系统"减弱动态效果"；无阻塞式动画。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 跳枪/温度导致油耗波动被误读 | 区间油耗标"参考值"+ 引导文案 |
| 只有Trip表的车 | distance_since_last 字段兜底 |
| 换机/卸载丢数据 | 一键导出 CSV + 本地备份文件 |
| 需求膨胀 | MVP 锁死 M1–M3，二期功能进 backlog 不进首个 APK |
