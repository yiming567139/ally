## 2. 技术选型（结论：方案 1 · Flutter）

针对你问的"前端尽量做好看，用 1 还是 2"——**推荐 Flutter**：

| 对比项 | Flutter | React Native / Expo |
|---|---|---|
| 渲染方式 | 自绘引擎（Impeller），**所有机型像素级一致**，深色模式/自定义 UI 不受平台组件限制 | 映射原生组件，定制深度依赖第三方库 |
| 动效表现 | 动画系统是框架核心能力（Hero、隐式动画、spring 曲线），**做"好看"成本低** | 需要额外库（Reanimated），调体验更费劲 |
| 图表 | fl_chart 成熟好用 | victory-native / react-native-svg 手工感重 |
| 适合度 | 工具类 + 重 UI 定制 = Flutter 主场 | 如果你本身熟 React/TS，则维护成本更低 |

> 结论依据：本项目 UI 全自定义（油量表、数字翻牌、图表卡片），Flutter 自绘 + 动画优势明显；不必顾虑 iOS/Android 双端一致性。

技术栈清单：

- **框架**: Flutter 3.x + Dart
- **状态管理**: Riverpod
- **本地库**: drift（SQLite ORM，类型安全、响应式查询，数据变动 UI 自动刷新）
- **图表**: fl_chart
- **图标**: lucide_icons（统一线性图标，禁用 emoji 图标）
- **提醒**: flutter_local_notifications（二期保养提醒）
- **字体**: 中文 MiSans / Noto Sans SC，数字与拉丁 Poppins（tabular figures）

## 3. 信息架构


## 5. 数据模型（drift / SQLite）

### vehicles 车辆表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT NOT NULL | 显示名，如「春风 450SR」 |
| displacement_cc | INTEGER? | 排量 |
| tank_capacity_l | REAL? | 油箱容积（用于剩余油量/续航估算） |
| fuel_grade | TEXT? | 常用标号 92/95/98 |
| odometer_initial | REAL NOT NULL | 建车时的总里程基准 |
| purchase_date | TEXT? | |
| is_archived | INTEGER DEFAULT 0 | 归档不删除 |
| created_at | TEXT | ISO 8601 |

### fill_ups 加油记录表（核心）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| vehicle_id | INTEGER FK → vehicles | |
| filled_at | TEXT NOT NULL | 加油时间，默认现在 |
| odometer | REAL NOT NULL | 总里程读数 |
| is_full_tank | INTEGER NOT NULL | **是否加满（计算边界开关）** |
| volume_l | REAL? | 升数（录入方式 A 直接填） |
| total_price | REAL? | 金额（录入方式 B） |
| price_per_l | REAL? | 单价（B 方式与 volume_l 互算） |
| distance_since_last | REAL? | 无总里程表的车：填「距上次行驶里程」 |
| station / note / photo_path | TEXT? | 可选 |
| created_at / updated_at | TEXT | |

**录入校验规则**：`volume_l` 与（`total_price` + `price_per_l`）至少存在其一；odometer 小于上一条 → 黄色警告但允许保存（录错总里程常见）；删除需二次确认 + 可撤销 toast。

### maintenance_logs 保养表（二期）

type(机油/机滤/空滤/链条/火花塞)、odometer、date、interval_km、interval_days → 推算下次提醒。

## 6. 核心算法：满箱法

**原则：只有「上次加满 → 本次加满」构成的区间，油耗才可信；未加满的记录只参与累计，不作为计算边界。**

对每辆车按 `filled_at` 排序后：

1. 取所有 `is_full_tank = 1` 的记录为锚点。
2. 相邻锚点 A → B 构成一个计算段：
   - `distance = B.odometer − A.odometer`
   - `fuel = sum(volume_l of records in (A, B])`（B 这一笔补满了油箱缺口，所以含 B 不含 A）
   - `区间油耗 L/100km = fuel / distance × 100`；`km/L = 100 / L100`
   - `每公里成本 = 段内 total_price 之和 / distance`
3. 边界情况：
   - **第一条记录**：仅作基准，不算油耗；
   - **最后一个加满锚点之后**（尾巴）：进入「本箱进行中」状态，不显示区间油耗，只累计已跑里程/已加油量；
   - **无总里程表的车**：用 `distance_since_last` 直接累加段里程；
   - odometer 倒退/相等：标记异常，提示检查，该段不计入均值；
   - **误差提示**：小油箱「跳枪」早晚误差可达 ±0.3L/100km，历史页区间油耗标注"参考值"，引导文案建议固定同一把枪自动跳枪。
4. 全局指标：平均油耗 = 首个锚点后总油耗 / 总里程；单位设置支持 L/100km ↔ km/L 全局切换。

```
│ └──────────────────────────┘ │
```

### 7.2 记一笔（Bottom Sheet，加油站单手场景）

- 字段顺序即操作顺序：**金额/升数输入**（大数字键盘，可切换）→ 单价（默认带上一次）→ 里程（默认上次 + 常骑日均值预填）→「加满」大开关（默认开，未加满显示醒目琥珀描边提醒"不计入区间油耗"）→ 时间（默认现在）→ 站点/备注（折叠）。
- 校验就地显示（on blur）；保存按钮在无油量数据时禁用。
- 保存：haptic 轻震 + sheet 下滑收起 + 首页新油耗卡片高亮浮现。

### 7.3 记录（历史）

- 倒序按月分组；每条：日期、站点、升数、金额、**区间油耗**。
- 未加满记录：灰色卡片 + 「部分」角标，油耗位显示"—"。
- 左滑编辑/删除；删除后 toast 可撤销。

### 7.4 统计

- 油耗趋势折线（区间油耗 + 均值虚线，点击数据点显示详情 tooltip）；
- 月花费柱状图；油价走势；加油站/标号对比横向条形图；
- 时间粒度切换（近 3 月 / 6 月 / 全部）；空状态给插画 + 引导，不出空白坐标轴。

### 7.5 车辆管理 & 设置

- 车辆：列表 + 新增表单（名称必填，油箱容积/标号/初始里程建议填）。
- 设置：油耗单位、主题（跟随系统/深/浅）、导出 CSV、备份到文件、恢复、关于。

## 8. UX 质量红线（实现时逐条验收）

1. 无 emoji 图标；lucide 线性图标统一线宽，同一层级不混用 filled/outline。
2. 深浅两套主题**分别**验对比度：主文字 ≥ 4.5:1，次文字 ≥ 3:1；分隔线两套都可见。
3. 所有可点元素有按压反馈（scale/透明度），不位移布局。
4. 表单 label 常显（不靠 placeholder）；错误提示就地 + 给修复建议。
5. 底部导航 ≤ 5 项、图标+文字；返回行为可预期，返回恢复滚动位置。
6. 数字一律 tabular figures；列表虚拟化（记录 > 50 条）。
7. 安全区适配（手势条/挖孔），固定底栏留出 padding。
8. 尊重系统"减弱动态效果"；无阻塞式动画。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 跳枪/温度导致油耗波动被误读 | 区间油耗标"参考值"+ 引导文案 |
| 只有Trip表的车 | distance_since_last 字段兜底 |
| 换机/卸载丢数据 | 一键导出 CSV + 本地备份文件 |
| 需求膨胀 | MVP 锁死 M1–M3，二期功能进 backlog 不进首个 APK |
